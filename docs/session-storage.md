# Session storage

Use `SQLiteSessionExtension(path)` instead of the in-memory accumulator. It owns
the SQLite storage and restores history before every request. The lower-level
`SessionPersistenceExtension(storage)` remains available for custom storage.

```python
from zett_agent import SQLiteSessionExtension

history = SQLiteSessionExtension()
agent = await Agent.create(
    model,
    config=AgentConfig(session_id=session_id),
    extensions=[
        history,
        ToolGuidelinesExtension(),
        CompactionExtension(model),
    ],
)
await agent.run("Hello")
history.close()
```

Storage defaults to `~/.zett-agent/sessions.sqlite3`. Pass an explicit filesystem
path to select another database. No application session table is required; the
first message starts its session log. Register persistence before extensions
that compact or modify request context.

## Restore on every request

`on_message` loads the latest snapshot and every newer raw message into each
request's fresh state, before the incoming user message is appended.
It replaces the conversation tail instead of adding a second copy. System
instructions remain at the front. An already constructed Agent therefore sees
storage changes made between requests.

`MessageAppendedEvent` persists each new user, complete assistant, and tool message.
Restored messages and synthetic checkpoints do not produce raw-log entries.
`CompactionEvent` saves the rewritten context; `on_success` only releases request
bookkeeping. Ordinary successful requests do not create snapshots: their messages
are replayed from the raw log after the latest compaction boundary. Before the
first compaction, restore the entire raw log without a snapshot.
Sequence and snapshot-version checks reject stale writes.

## Tables

The Agent owns two ORM-defined tables, without foreign keys or cascade rules.

| Table | Field | Meaning |
| --- | --- | --- |
| raw_messages | id | Time-ordered message UUIDv7 |
| raw_messages | session_id | Owning session UUID |
| raw_messages | request_id | Request UUIDv7 supplied by the application or generated by the extension |
| raw_messages | sequence | Monotonic original-message position within the session |
| raw_messages | role | Numeric system/user/assistant/tool enum |
| raw_messages | content | Readable message text |
| raw_messages | message_json | Complete typed runtime message envelope |
| raw_messages | created_at | UTC time this immutable message was appended |
| raw_messages | updated_at | Equal to created_at; raw messages are never rewritten |
| session_snapshots | id | Time-ordered snapshot UUIDv7 |
| session_snapshots | session_id | Owning session UUID |
| session_snapshots | version | Increasing immutable snapshot version |
| session_snapshots | base_sequence | Highest original-message sequence covered by the entire snapshot |
| session_snapshots | messages_json | Ordered checkpoint and active recent dialogue; system instructions are rebuilt |
| session_snapshots | created_at | UTC creation time of this version |
| session_snapshots | updated_at | Equal to created_at; context changes create a new version |

`(session_id, sequence)` is unique in the raw table. `(session_id, version)` is
unique in snapshots. A snapshot is created only when context is compacted.
The latest version is active, so no mutable is_active flag is needed.

Restore `snapshot.messages_json` followed by raw entries with
`sequence > snapshot.base_sequence`. Never interpret compacted list offsets as
raw-log positions. Raw messages and snapshots retain their complete typed runtime
envelopes. `list_raw_messages()` exposes typed, paginated Raw Log records for history UIs and
auditing. `delete_session()` explicitly removes both table ranges for a session.
Storage can be closed and reopened without depending on a Zett process.

Tests use temporary SQLite databases. Existing Zett application data is not
migrated or deleted. Raw assistant messages are emitted on complete model responses.
